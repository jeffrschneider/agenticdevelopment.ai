The family of standards

No two teams have ever agreed on a development lifecycle.

So this one is built to be tailored. Change the stages, change who holds them, and every agent still ends the same way: with a signed Descriptor and a registration, and, when a platform runs it, an Agent Package.

Read the stages Get the code

Every stage says who holds it and how you know it's done.

This reference runs through twenty-five stages, from the first idea to the last day. Each names its role, what it's given, what it hands back, and how you know it's done. Here's one.

Test

Role
test writer
Given
the statement of the job
Hands back
the suite, and what no test could be written for
Done when
the suite fails against empty stand-ins, and notices each program removed
Why here
Tests come before the program, from the statement, so a test can't pass by agreeing with a mistake. (Yes, people argue about this.)

Join the lifecycle where you are.

Everybody starts from something: an idea, a prototype, working code, a package. Find the furthest one you have, and start at the stage right after it.

  1. If you already have an idea,start at Requirements
  2. If you already have a prototype,start at Test, then Code
  3. If you already have working code,start at Package on-ramp
  4. If you already have a package or an image,start at Release on-ramp, then Deploy goes live
  5. If you already have a remote agent with an A2A endpoint,register it; add what it refuses and records
  6. If you already have an agent connected to a network through a node,it's already on; finish its Descriptor
  7. If you already have agents running on a platform,start at Run and Change

See every asset, and which ones are required

Everyone agrees on the ending.

However your lifecycle runs, every agent ends with a signed Descriptor and a registration. An agent a platform runs also arrives as an Agent Package: the declaration, the parts, a manifest and a digest.

Our package maker is the easy on-ramp to the mesh. Any other tool works, as long as the package is valid.

A platform checks every package before it installs or updates anything, so every agent it runs meets the same gate, whoever built it.

Any agent can hold a role, and so can you.

Every stage names a role, not a product. The roles are written down at agentroles.ai, so anyone can build an agent to one, and a person can hold any of them.

  • spec writer
  • test writer
  • code writer
  • package maker
  • deployment manager
  • incident recorder
  • or a person

Start from working code, not a blank page.

Reference agents for eleven roles are open source under Apache-2.0, at github.com/CommonAgent/adlc.
