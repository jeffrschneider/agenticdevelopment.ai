The family of standards

Build your agent any way you like, but it must pass the gates.

You don't have to follow our stages. You don't have to use our tools or our reference agents. You can start anywhere and build any way you like.

We insist on one thing: a small set of gates. A gate is a point where work stops until a condition is met. A gate checks the agent and its records. It doesn't check how the agent was built. Skipping a step costs nothing. Shipping an agent that fails a check does. An organization can add gates of its own.

The six gates

Release

Sits
between Package and Release
Requires
a valid package and a valid declaration
Enforced by
the package maker
If refused
Nothing is released. The package maker names each problem.
Status
required

Production deploy

Sits
between Release and a deploy to production
Requires
a current audit pass for the package digest
Enforced by
the deployment manager
If refused
The agent doesn't reach production. It can still run in dev or test, which need no audit pass.
Status
required

Listing

Sits
before the catalog lists an agent, at Source
Requires
a current audit pass
Enforced by
the catalog
If refused
The catalog doesn't list the agent. Nobody finds it there until it passes.
Status
required

Acceptance

Sits
between delivered and accepted, at Acceptance
Requires
a person's recorded yes against "done"
Enforced by
the person who asked
If refused
The request stays open. The person's no says what's missing.
Status
required

Promote

Sits
inside Update, between the candidate and the live version
Requires
a candidate that passed, and no open dependency debt in the ledger
Enforced by
the deployment manager
If refused
The live version keeps running. The candidate waits. A rollback is never blocked, and it's recorded.
Status
required

Decommission

Sits
before an agent is retired, at Decommission
Requires
no stranded work, and no open dependency debt in the ledger
Enforced by
the deployment manager
If refused
The agent keeps running. It retires once its work is done and its debts are closed.
Status
required

An organization can add gates of its own.

An organization adds a gate through its own audit checklist. The checklist is a standing asset. A person approves each version. Each check has a level: info, warn or refuse. A check set to refuse stops an agent at the production deploy and listing gates.

For example, an organization can require a security statement before production. It raises the security statement check from info to refuse. The auditor then fails any agent that has no signed security statement. Without a current audit pass, the deployment manager refuses to deploy that agent to production.
