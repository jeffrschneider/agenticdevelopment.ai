The family of standards

Join the lifecycle where you are.

Every lifecycle runs on its assets: the statement, the tests, the code, the package, the records. Everybody starts with some of them already.

Start from the furthest thing you already have.

  1. If you already have an idea,start at RequirementsWrite the statement of the job. Everything after is checked against it.
  2. If you already have a prototype,start at Test, then CodeWrite the statement of the job from your prototype, then Test.
  3. If you already have working code,start at Package on-rampBring the statement and your programs; Package lists every program.
  4. If you already have a package or an image,start at Release on-ramp, then Deploy goes liveGive it an address and a signed build record, then deploy it.
  5. If you already have a remote agent with an A2A endpoint,register it with a platformIts Agent Card gives most of its Descriptor. Add what it refuses and what records it keeps. No package needed.
  6. If you already have an agent connected to a network through a node,it's already on; start at DocsFinish its Descriptor so people can find it.
  7. If you already have agents running on a platform,start at Run and ChangeWatch them, judge their work, and change them with a record.

Only the ending is fixed.

Everything before the package is yours to shape. Every agent, wherever it runs, ends with a signed Descriptor and a registration that points at it. An agent a platform runs also has its Agent Package and the records each later stage leaves.

Standing assets belong to the organization, not to one agent.

Every asset above is made for one agent. A standing asset is a document that many agents read, such as a brand profile or a glossary. An organization, a team or a person keeps it. Its schema says what kind of document it is. Each version has its own digest. A person approves each version before any job uses it. It never contains a secret.

Every agent draws on three things.

  • SetupSetup is what the agent is connected to, and with which keys. The operator does it once, at install. Secrets live here and nowhere else. A person preparing a job is never asked for any of it.
  • LibraryThe library contains the organization's shared material and defaults, such as its brand and its templates. Standing assets live here.
  • This jobThis job is what you give the agent, and your options for this run.

Architecture decides which standing assets an agent reads, with a reason for each. Design declares those same assets as can_use entries. Package checks that each entry names a known schema. Every run record names the version of each standing asset the run used.

one can_use entry
{ "schema": "https://schemas.example.org/brand/v1",
  "reads": ["colors", "logo"], "required": false,
  "does": "styles the slides it makes",
  "without": "uses plain black text on white" }

The audit checklist is a standing asset like the others. Each check has an id, the rule, the reason for it, its kind, the stage that fixes it, its level and the date it applies from. The kind is design-time, run-time or stage-record. The level is info, warn or refuse. A check with no test to run it shows in the report as not checked. It is never skipped.

By default, every agent needs a signed Descriptor and registration. An agent a platform runs also needs its package, signed build record, deployment record and conformance verdict. The auditor runs every other check itself. Other artifacts, such as a design or a security statement, count as evidence if they are signed for this package. Checks on them are info only. An organization's own checklist may raise any info check to warn or refuse.

The usability report is read the same way. The verdict is usable, usable with findings, or not usable. The default checklist shows the report as evidence for this package. An organization that wants every agent tested by a person, or by an agent, raises that check to refuse.

Layers decide which version an agent reads.

Five layers can set a standing asset. From widest to closest, they are the publisher, the organization, the team, the person and the job. For a preference, the closest layer that gives a value wins. For a rule, the tightest wins. A closer layer may narrow a rule but never widen it. A company that republishes an agent becomes the publisher for its own buyers.

Sometimes one company's agent works for another company. The brand, style and templates then come from the requester's library. The requester grants them for that job only. Build and check standards come from the operator's library. The agent never fills a gap in the requester's material with its operator's own.
