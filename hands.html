Who holds a stage

Four levels, and what has to be true before a stage moves up one.

Saying a lifecycle is "agentic" is not useful, because no lifecycle is agentic all the way through and none is entirely manual either. What is useful is saying, stage by stage, who holds it. These are the four levels used across this site. They describe a stage as it is practiced, not a product and not an ambition.

The four

LevelWhat it meansWho is accountable
person A person does the work. They may look things up, but nothing else produces the output. the person
person + model A person drives and a model produces. The model has no identity of its own, and whatever record exists belongs to the session rather than to the work, so there is no address to ask. Every session starts over. the person
agent, approved An agent does the work and files the result, and a person says yes before it takes effect. The agent has an identity, keeps records, and can be asked afterwards. shared: the agent for the work, the person for the decision
agent An agent does the work and the result stands without anybody approving it. This is only safe where a check exists that the agent does not control. the agent, and whoever runs it

The distinction that matters

The interesting line is not between a person and a model. It is between a model and an agent, and it is the second and third rows above.

A model used inside somebody's session is a tool. The session may well be logged, and a transcript is a record, so the difference is not that nothing is written down. The difference is that the record belongs to the person's session rather than to the work: nothing downstream holds a reference to it, nothing is obliged to keep it, and there is no address to ask. The person is the index. That is workable and it is how most of this stage of the industry runs, but it does not compose, because the parts only exist while somebody is watching them.

An agent has an address, keeps records, and can be asked afterwards what it did and why. That is what lets one stage hand to the next without a person in the middle carrying the context.

So "person + model" is not a weaker version of "agent". It is a different arrangement, where the human is doing the part an agent would need an artifact for.

Moving a stage up a level

Each step up has one requirement, and it is not a better model.

From person to person and model needs nothing but the model, which is why this step happened everywhere, quickly, and why it is not the interesting one.

From person and model to an agent with approval needs the handoff. The stage before has to produce something the agent can be given, and the stage has to produce something the next one can read. Until both exist, an agent here is a model with a launcher and somebody still has to hold the context.

From an agent with approval to an agent alone needs a check the agent does not control, written before the work, by something that is not the thing doing the work. Without it, removing the approval removes the only thing standing between a mistake and a result. With it, the approval is the ceremony and the check is the substance, and the ceremony can go.

Why approval is not a stage of maturity

It is tempting to read the four levels as a ladder where the top is the goal. Some stages should stay at agent, approved permanently, and not because the agent is not good enough.

There are two different reasons a stage keeps a person in the loop, and it is worth knowing which one applies. Either the check that would make the agent safe on its own has not been written, which is a gap and will close; or the act is one a person should own whatever the agent is capable of, which is not a gap and will not close.

Deploying, configuring and decommissioning change the world in ways that are awkward to undo, and the approval is not a check on the agent's competence. It is a record that a person decided. That record is worth keeping even when the agent is more reliable than the person approving it, which it often is.

The right question for each stage is not how high it can go. It is whether a person is in the loop to catch the agent, which is a gap to close, or to own the decision, which is not. Deploy, Configure and Decommission are the second kind. Code, Test and Review are the first.
