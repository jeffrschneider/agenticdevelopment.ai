Implementations

What holds each stage today, on the one mesh this draft is written alongside.

Everything listed is on AgentMesh. The roles they declare are published separately at agentroles.ai, so another mesh could hold the same roles with entirely different agents, which is the point of publishing roles at all.

The stages that are held

StageAgentRole it declares
Build and package agentbuilder agent builder
Release agentbuilder agent builder
Deploy deploymgr deployment manager
Configure deploymgr deployment manager
Acceptance agentevaluator agent evaluator
Update deploymgr deployment manager
Decommission deploymgr deployment manager

Seven stages, three agents. The concentration is not an accident: these are the stages built out of artifacts, so one agent can hold several of them by reading the same package at different moments.

One mesh is one data point. The claim on the rest of this site, that the stretch from Build to Acceptance moved first because it already had artifacts, is an observation drawn from here and from how provenance tooling was built elsewhere. It is offered as an explanation worth arguing with, not as a survey.

The stages that are partly held

Docs. The document format is defined at agentdoc.net and is assembled from what an agent already declares, never authored. Assembling it is a tool rather than an agent today, so the stage has a defined output and no role holding it.

Eval. One agent grades the quality of one kind of work, against what was asked for. That is a working instance of the stage rather than a general answer.

Monitor. Liveness across the fleet is watched by supervising programs rather than by an agent. The important property, that silence is treated as a failure rather than as no news, holds either way. The map marks this stage as a person's, because a program that watches keeps no record anybody can ask it about afterwards.

What is not held at all

Requirements, Design, Code, Test, Review, Security review, Publish, Cost, Incident response and Rollback. On this mesh as everywhere else, a person and a model do these, in a session, with the person carrying the context between them.

The honest version of that sentence is worth saying plainly: the agents on this mesh were written by a person and a model working together, and nothing in the lifecycle wrote them. The stages that build, ship and prove an agent are held by agents. The stage that writes one is not.
