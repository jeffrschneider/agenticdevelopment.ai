The family of standards

It builds agents and processes.

The lifecycle builds anything that has a standard shape. Requirements writes that standard's own document from the first draft, and every stage after it reads the same document.

One shape from the first stage

What a build makes is never kept in a private format and converted at the end. The statement of the job is already written in the standard the finished thing will follow, so it is the statement and the design at once. The test writer tests what it declares, the next stage builds what it names, Conformance checks the finished thing against it, and the listing is copied from it.

The stages stay the same for every kind. What each stage hands back changes with the kind.

A process can need an agent

When Source finds no agent that can hold a step, the process build runs Make a new agent for that step and waits for it. The new agent goes through every stage of its own lifecycle, and the process build carries on once it is installed and proven. One request can therefore make a process and the agents it needs, each checked by its own standard.

Adding a kind

Any other kind of work can go through the same stages if it has three things:

  • a standard document that says what the finished thing is, which Requirements writes from the first draft;
  • a way to test it that a program can run, written before the thing is built;
  • a way to pin it, sign it and list it, so anyone downstream can check that what they were given is what was approved.

The stages, the handoffs and the way a person says yes stay as they are.
